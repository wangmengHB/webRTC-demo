Every game needs a player! We'll draw Steve as a simple blocky character — body, head, and a little face. We store the player's position in variables so we can move it later.

2
Listen for Keys
⌨️

Now let's make the player move! We use addEventListener to listen for key presses. When the player presses an arrow key, we change playerX or playerY.

After moving, we redraw the whole canvas — this is called a "render loop" and it's how every game works!

🕹️ Game loop! Real games redraw the screen 60 times per second. Each frame clears the old positions and draws new ones — like a flipbook!

3
Stay Inside the World
🚧

Right now the player can walk off the screen! We need to add boundary checks — if statements that stop the player from going too far.

We check: is the new position outside the canvas? If yes, don't move there!

🧱 Boundaries everywhere! In every game, invisible "walls" stop characters from falling out of the world. Even Minecraft has a world border!
Add boundary checks ↓
4
🏆 Smooth Movement!
🎮

The movement is a bit "jumpy" because we only move when a key is pressed. Real games use a game loop — code that runs 60 times per second using requestAnimationFrame.

We track which keys are held down and move every frame. This feels much smoother!

⚡ 60 FPS! "FPS" means frames per second. 60 FPS means the screen redraws 60 times every second — that's why smooth games feel so good!
